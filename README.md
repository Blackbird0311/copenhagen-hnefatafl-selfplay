# Copenhagen Hnefatafl: 3,000 Tactical Self-Play Games

**A freely reusable dataset of 3,000 synthetic Copenhagen 11×11 Hnefatafl games.**

Generated in October 2026 by John Cutting for the Chronolympics project, using a custom fast tactical self-play mode built locally on the [TaflZero](https://github.com/sovelin/taflzero) rules engine. This release is intended for developers, researchers, game designers, and players who want complete machine-readable or human-readable tafl move histories.

**All original game records and the dataset-specific metadata are dedicated to the public domain under [CC0 1.0 Universal](https://creativecommons.org/publicdomain/zero/1.0/). No permission, payment, or attribution is required.** You may copy, modify, redistribute, analyze, train on, or use them commercially. See [LICENSE](LICENSE).

> **Data quality note:** These are games between *heuristic agents*, **not human tournament records** and **not full-strength TaflZero neural-network/MCTS games**. The moves are legal according to the TaflZero rules engine, but some decisions are strategically weak. Do not present the collection as expert play.

## Downloads and files

The release package is structured as follows:

```text
README.md
LICENSE
index.csv
opentafl_games.zip
  └── otn/game_00001.otn ... game_03000.otn
games.jsonl.gz
```

- **`games.jsonl.gz`** — the complete, unfiltered source recordings, one JSON object per line, including draws. This is the **authoritative source archive** for this release.
- **`opentafl_games.zip`** — 3,000 numbered `.otn` files containing OpenTafl-style game records, moves, capture annotations, and metadata. These are a convenience export; compatibility with every OpenTafl reader has **not** yet been independently confirmed.
- **`index.csv`** — `game_id`, `filename`, `winner`, `termination`, and `move_count`, for browsing and filtering.


## JSONL format

Each nonempty line of the uncompressed archive is a separate game:

```json
{
  "variant": "Copenhagen11x11",
  "board_size": 11,
  "winner": "attackers",
  "termination": "atk_capture",
  "moves": ["h11h9", "g7g10"]
}
```

*The example above illustrates the field layout and notation; it is not presented as a complete game.* The coordinates use files `a` through `k` and ranks `1` through `11`. Each move concatenates its starting and destination squares, such as `h11h9` = `h11` to `h9`. TaflZero uses this algebraic coordinate scheme.

`winner` is `attackers`, `defenders`, or `draw`. The `termination` field explains the recorded ending. The generator recorded complete move sequences rather than per-turn search diagnostics, neural evaluations, or timestamps. The JSONL archive does **not** guarantee a unique game ID in each row; the row number is its stable identifier within this release.

Quick use in Python:

```python
import gzip
import json
from collections import Counter

with gzip.open("games.jsonl.gz", "rt", encoding="utf-8") as f:
    games = [json.loads(line) for line in f if line.strip()]

print(len(games))
print(Counter(game["winner"] for game in games))
print(games[0]["moves"][:10])
```

## OpenTafl-style notation

A typical `.otn` file includes headers and numbered turns:

```text
[event:TaflZero Tactical v4 Self-Play]
[attackers:Tactical v4]
[defenders:Tactical v4]
[result:0]
[termination:Generation move limit reached]
[variant:Copenhagen 11x11]
[rules:dim:11 atkf:y sw:s efe:y start:/.../]

1. h11-h9 g5-g3
2. g1-g2 g3-e3
```

The actual files contain the full initial position, not `...`. Moves are converted from TaflZero notation; capture locations are generated by applying moves through TaflZero's rules engine and comparing resulting board states. Multi-piece captures are represented with slash-separated captured squares. King moves and captures are annotated separately.

**Rules compatibility caveat:** These recordings have **attackers moving first** (`atkf:y`) because that is how the local generator was configured. Do not change this to a defenders-first setting when importing: the recorded move order would no longer match. The `.otn` records should be tested in your own reader before treating the export as fully interoperable.

## How the games were generated

The dataset was produced by a modified, fast self-play path in TaflZero using a custom **Tactical v4** evaluator. It is deliberately less expensive than full neural-network-guided Monte Carlo tree search. In general, the process:

1. Enumerated legal moves under TaflZero's Copenhagen rules.
2. Scored immediate captures, king advancement, escape-corner positioning, and king mobility.
3. Screened promising candidate moves for immediate opponent wins and capturing replies, using selective short lookahead rather than unrestricted minimax.
4. Applied modest randomized scoring to vary the game trajectories.
5. Stopped games at decisive rule-defined outcomes or generator-imposed draw limits.

The recorded games were generated using approximately six leading candidates for reply analysis; the exact behavior is determined by the modified local Tactical v4 generator. **The pre-trained `default_nn.onnx` file was not used to make move-selection decisions in this fast mode.** Running the engine with a `--net` argument does not make these neural-network games.

Generation took place locally on a consumer Fedora laptop. This package contains the resulting records, not the model, engine binary, modified TaflZero source code, or a complete reproducible training environment.

## Validation and limitations

- The legal move sequences were replayed using TaflZero's Copenhagen 11×11 board and move generator to produce the OpenTafl-style records.
- A 1,258-game **separately balanced subset** was also checked against board-state replay data for use in Chronolympics; that subset is **not** the complete public dataset.
- The ZIP archive was successfully checked for corruption using `unzip -t`.
- **Remaining verification:** A separate termination-validator implementation did not yet recognize `atk_surrounded`. Those ten game-ending labels still require an independent terminal-rules check before a claim of complete *outcome* validation. Legal move replay alone does not verify that a reported ending is correct.
- A valid legal move is not necessarily a good strategic move. The engine may exhibit repetition, avoidable mistakes, or unexpected outcomes.
- A draw caused by `draw_limit` or `draw_nocapture` is a **generator-imposed stop**, not necessarily a draw adjudicated under official competitive rules.
- OpenTafl reader interoperability has not yet been fully tested.

If you find a malformed record, incompatible notation, or questionable terminal classification, please open a GitHub issue with the game number and ply.

## Relationship to Chronolympics

These recordings were originally prepared for [Chronolympics](https://chronolympics.com/), a fictional Olympic sports simulation. Its presentation system selects from a separate balanced subset of 1,258 decisive games (629 attacker victories and 629 defender victories, each 30–150 moves) so that its simulated athlete results can be determined independently of Hnefatafl's asymmetric sides.

**That balancing is a Chronolympics design choice, not a claim about actual Copenhagen Hnefatafl competitive balance.** The public release deliberately retains the original unbalanced results, including all draws.
